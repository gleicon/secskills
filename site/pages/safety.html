Safety model

secskills tests systems, so its controls live in the binary rather than in convention. This page says what each control does and where it stops. None of it replaces written permission from the system's owner.

The authorization gate

Commands that send traffic to a target (discover, test, sandbox, watch, integrity, enrich, leakcheck, dbcheck, kprobe) refuse to run until one of these holds:

  • you pass --confirm, stating you hold written authorization, or
  • a scope file authorizes the target.

A scope file counts only when all of the following are true. Otherwise it is ignored and the gate asks again.

  • authorized: true is set.
  • The expires date has not passed.
  • The target is listed under targets and not under out_of_scope. A listed domain covers its subdomains; a listed CIDR covers its addresses.
  • The file is owned by you and not writable by group or others.
# .secskills-scope.yml
engagement: acme-q4
authorized: true           # only with written authorization
engagement_type: black-box
confirmed_by: you@example.org
expires: 2026-12-31
intrusive: false
targets:
  - app.example.com
out_of_scope:
  - payments.example.com

For network blocks, authorization is checked for every IP, and out_of_scope entries are skipped even under --confirm. A block wider than /20 needs --allow-large in addition.

Non-destructive by default

  • Default tests only read. They do not create accounts, upload files, or write to the target.
  • Write and credential tests need --intrusive and a second, separate --intrusive-confirm. dbcheck always needs both, and it tries only a short fixed list of vendor default credentials, never a wordlist.
  • No denial-of-service, no race triggers, no fault injection, at any profile. Kernel probes send one packet and report reachability, never patch state.
  • Requests are rate-limited in the engine (SECSKILLS_RATE, default 5 per second), and free data sources are throttled with backoff.

Network guards

  • Outbound fetches refuse non-HTTP schemes and any host that resolves to a private, loopback, link-local, metadata, or reserved address. The sweep's probe client checks again at connect time, so DNS rebinding cannot slip past it.
  • Redirects are not followed, so a target cannot bounce a probe somewhere unauthorized.
  • Requests that carry your credentials verify TLS. --insecure-auth turns that off for self-signed targets, at your explicit request.
  • Webhook delivery requires HTTPS, verifies the certificate, and logs only the scheme and host.

Target output is untrusted

Banners, titles, and page content come from the target and may be written to manipulate whoever reads them, including an AI agent. Before any of it reaches a finding, report, or your terminal:

  • control characters and invisible or direction-changing Unicode are stripped;
  • known prompt-injection phrases are replaced with a visible marker;
  • newlines are collapsed so a value cannot fake a new conversation turn;
  • credential-like values in evidence samples are masked.

Shell commands stored for reproduction quote every target-derived value. Over MCP, an agent gets read-only tools; it cannot start a live scan.

Engagement data stays with you

Findings, evidence, workdirs, and scope files describe someone else's systems. secskills keeps them local and never sends them anywhere you did not ask for.

  • The findings store (~/.secskills-findings/) and workdirs are created readable by you only. Treat them like a credentials store, and do not commit them; the repository's .gitignore already excludes scope files and generated reports.
  • Reports include the fact of an exposure and the names of exposed keys, never credential values.
  • API keys for Shodan and Censys are read from the environment or tool config and never written into reports.
  • Runs can be signed (secskills attest --sign) so a recipient can verify a report was not changed after the fact.

Reporting a problem in secskills

Keep it private. Do not describe a vulnerability, or include any target data, in a public issue, discussion, pull request, or commit. Contact the maintainer directly through the repository owner's GitHub profile. A person reads and handles every report; there is no automated intake.

Never include engagement data (findings, evidence, workdirs, scope files, credentials) in a report about secskills itself.
