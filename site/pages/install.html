Install

secskills is a single static binary with its knowledge base and rules built in. Pick one way to get it, then let secskills doctor tell you which optional tools would widen coverage.

With Go

Needs Go 1.27.4 or newer. With an older Go, the go command downloads 1.27.4 automatically (unless GOTOOLCHAIN=local).

go install github.com/gleicon/secskills/cmd/secskills@latest
secskills version

The binary lands in $(go env GOBIN), or $(go env GOPATH)/bin when GOBIN is unset. Make sure that directory is on your PATH. Pin a release with @v{{VERSION}}.

From a release binary

Each release has binaries for linux and darwin (amd64, arm64) and windows (amd64), built without CGO, plus a SHA256SUMS file. Check the download against it before running it.

Linux

base=https://github.com/gleicon/secskills/releases/latest/download
curl -fLO $base/secskills-linux-amd64
curl -fLO $base/SHA256SUMS
grep ' secskills-linux-amd64$' SHA256SUMS | sha256sum -c -
install -m 0755 secskills-linux-amd64 ~/.local/bin/secskills

macOS

base=https://github.com/gleicon/secskills/releases/latest/download
curl -fLO $base/secskills-darwin-arm64        # Intel: secskills-darwin-amd64
curl -fLO $base/SHA256SUMS
grep ' secskills-darwin-arm64$' SHA256SUMS | shasum -a 256 -c -
install -m 0755 secskills-darwin-arm64 /usr/local/bin/secskills

Windows (PowerShell)

$base = "https://github.com/gleicon/secskills/releases/latest/download"
Invoke-WebRequest "$base/secskills-windows-amd64.exe" -OutFile secskills.exe
Invoke-WebRequest "$base/SHA256SUMS" -OutFile SHA256SUMS
(Get-FileHash secskills.exe -Algorithm SHA256).Hash.ToLower()
Select-String "secskills-windows-amd64.exe" SHA256SUMS   # the two hashes must match

The kernel reachability probe (kprobe) is Linux-only, and the headless capture kit scripts need a POSIX shell.

From source

git clone https://github.com/gleicon/secskills
cd secskills
make install        # go install ./cmd/secskills
make test           # unit tests plus the golden CLI suite

make dist cross-compiles every release target into dist/ with checksums.

Optional tools

secskills drives external tools when they are present and skips them when they are not. The binary needs none of them, except Docker for sandbox mode; doctor fails only in that case. Tools listed in the skills tier (curl, dig, jq, python3, git) are used by the agent skills and lib/ shell helpers.

secskills doctor                    # what is present or missing, with install commands
secskills doctor --mode discover    # only what one mode uses
secskills doctor --category report  # is a headless browser available for PDF?
ForTools
Source reviewast-grep (the engine for source), osv-scanner
Discoverysubfinder, dnsx, httpx (projectdiscovery), dig
Deeper testsnuclei, sslscan, katana, dalfox
Sandbox modeDocker
PDF reportsChrome or Chromium
Token hygienetldt
OSINT enrichmenta Shodan key (SHODAN_API_KEY), Censys (CENSYS_API_ID, CENSYS_API_SECRET)

The doctor warns when a different program with the same name shadows a tool, for example Python's httpx in place of projectdiscovery's.

Connect an agent

Install the binary first. The adapters below call it; they hold no logic of their own.

Claude Code plugin

claude plugin marketplace add gleicon/secskills
claude plugin install secskills@secskills

Adds the skills, including /secskills-intake, a guided interview that settles authorization, scope, and rules of engagement and writes the scope file for you.

MCP, in Claude Code or any client

claude mcp add secskills -- secskills mcp

Or in a client's JSON config:

{ "mcpServers": { "secskills": { "command": "secskills", "args": ["mcp"] } } }

The MCP server exposes read-only tools: doctor, kb_list, kb_get, recipes_get, source_scan, and a throttled, SSRF-guarded fetch. None of them can start a scan of a live target.

opencode

opencode reads AGENTS.md and the /secskills command from the repository. For MCP, add to opencode.json:

{
  "mcp": {
    "secskills": { "type": "local", "command": ["secskills", "mcp"], "enabled": true }
  }
}

Update or remove

go install github.com/gleicon/secskills/cmd/secskills@latest   # update
rm "$(command -v secskills)"                                    # remove the binary

Engagement data lives in ~/.secskills-findings/ and per-target workdirs. Removing the binary leaves it in place; delete it deliberately, it may hold sensitive evidence.
