Common cases

Recipes for the jobs people use secskills for most. Every command that touches a target assumes you hold written authorization for it.

Review a repository before it ships

No network, no gate. Needs ast-grep on PATH.

secskills source ./my-service
secskills source --json ./my-service > findings.json   # machine-readable

The rules cover real sinks (injection, deserialization, SSRF, secrets) and common smells in AI-written code. For a fix, read the guidance and a working example for your stack:

secskills kb injection
secskills recipes injection

Assess a web app you are authorized to test

  1. Settle scope first

    secskills profile app.example.com --output ENGAGEMENT-profile.md
secskills scope --init

    Edit .secskills-scope.yml: set authorized: true only once you have written authorization, list the targets and exclusions, and set an expiry. In Claude Code, /secskills-intake app.example.com does this as an interview.

  2. Check what the file allows

    secskills scope --validate

  3. Discover and test

    secskills discover app.example.com
secskills test app.example.com --deep

    With a valid scope file you do not need --confirm. Without one, add it to each command.

  4. Report

    secskills report --pdf app.example.com --output app.pdf
secskills report --audit app.example.com --output app-audit.md

Test the logged-in surface

secskills test app.example.com --confirm \
  --auth-token "$USER_A_TOKEN" \
  --auth-token-b "$USER_B_TOKEN"

The second identity drives the access-control differential: an object URL that returns the same private data to both users is flagged for manual confirmation. Use test accounts, not real users' sessions.

Credentialed requests verify TLS. If the target uses a self-signed certificate, they fail unless you add --insecure-auth, which lets anyone on the network path see those credentials.

Check that fixes landed

secskills report --retest app.example.com

Each finding is re-probed with a structured check, not a shell command, and marked fixed, still present, or regressed. To keep watching:

secskills watch app.example.com --confirm --interval 6h

Send findings to CI or a ticket tracker

secskills export --format sarif app.example.com --output secskills.sarif
secskills export --format cyclonedx app.example.com --output bom.json
secskills tickets app.example.com --format csv --output tickets.csv

Findings that share a root cause, such as TLS 1.0 and 1.1 on one host, collapse to a single ticket at the higher severity.

Change a severity after review

secskills findings show app.example.com          # find the finding_key
secskills override --target app.example.com --key <finding_key> \
  --severity LOW --reason "compensating WAF rule, verified"

The reviewed severity, reviewer, and reason are stored next to the automated value, and the report shows both.

Test a build in isolation

secskills sandbox ./build-context --confirm --port 8080

Builds the image, runs it in Docker, and tests only that container. It refuses to run without Docker rather than testing something unisolated.

Review a network block you own

For an ASN or CIDR under your authority. Authorization is checked per IP, and out_of_scope entries are never scanned.

  1. Sweep and enrich

    export SECSKILLS_WORKDIR=./acme
secskills discover --cidr 203.0.113.0/24 --confirm
secskills enrich    --workdir ./acme --confirm
secskills leakcheck --workdir ./acme --confirm

  2. Load vulnerability intelligence

    secskills feed kev
secskills feed epss
secskills feed nvd --product openssh
secskills feed nvd --product nginx

  3. Join and report, offline

    secskills cvematch --workdir ./acme
secskills lifecycle reconcile --workdir ./acme
secskills prefix-report --workdir ./acme --label "AS64500 203.0.113.0/24"

    CVEs in CISA KEV lead; the rest are ranked by EPSS. Every match is version-inferred, so treat it as a lead to confirm, since distributions backport fixes without changing versions.

Next week, refresh the feeds and re-run step 3. Nothing touches the network, and findings whose version moved out of range close as fixed.

Capture on a VM, analyze somewhere else

make bundle                                      # binary + scripts + feed cache
# on a VM near the target network:
CIDR=203.0.113.0/24 CONFIRM=yes ./capture.sh
# back home, no network needed:
OUT=./capture-203_0_113_0_24 ./process.sh

The workdir is append-only and resumable, so a capture can stop and restart without losing data. To split a large block across machines, secskills plan --asn AS64500 --shards 4 writes one prefix list per worker.

Let an agent help, safely

claude mcp add secskills -- secskills mcp

The agent can look up OWASP guidance, pull fix recipes, and scan source code. It cannot start a live scan: discover and test are not exposed over MCP and stay behind the CLI gate, where a person confirms authorization.
