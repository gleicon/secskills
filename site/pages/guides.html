Task-by-task walkthroughs. Each section gives the commands in order; the full guide in the repository adds what to read in the results and where to go deeper. Every command that touches a target assumes written authorization.

Penetration test of a web app

  1. Research and scope

    secskills profile app.example.com --output ENGAGEMENT-profile.md
secskills scope --init      # edit: authorized, targets, out_of_scope, expires
chmod 600 .secskills-scope.yml && secskills scope --validate

    In Claude Code, /secskills-intake app.example.com runs this as an interview.

  2. Map and test

    secskills discover app.example.com
secskills test app.example.com --deep
secskills test app.example.com --profile adversarial-readonly

  3. Logged-in surface

    secskills test app.example.com --auth-token "$USER_A" --auth-token-b "$USER_B"

    The second identity drives the access-control differential. Use test accounts.

  4. Report and verify

    secskills report --pdf app.example.com --output app.pdf
secskills tickets app.example.com --format csv --output tickets.csv
secskills report --retest app.example.com

Explore what a target exposes

secskills graph app.example.com --output graph/   # related domains, listed for scope review, never tested
secskills fetch crtsh "https://crt.sh/?q=%25.example.com&output=json"

secskills fp list                                 # technologies the fingerprints recognize

Scan an ASN or CIDR you own

  1. Size it and scope it

    secskills plan --asn AS64500 --shards 1 --out ./plan   # prefixes and address counts, no target traffic

    List the CIDRs under targets: in the scope file. Authorization is checked per IP.

  2. Sweep one prefix, then widen

    secskills discover --cidr 203.0.113.0/24
secskills enrich    203.0.113.0/24
secskills leakcheck 203.0.113.0/24
secskills discover --asn AS64500

  3. Join with intelligence, offline

    secskills feed kev && secskills feed epss && secskills feed nvd --product openssh
secskills cvematch 203.0.113.0/24
secskills report --render 203.0.113.0/24

    Triage open datastores first, then exposed .env/.git, then KEV-listed CVE leads. CVE leads come from banners: confirm the running build.

  4. Every week

    secskills feed kev && secskills feed epss
secskills cvematch 203.0.113.0/24
secskills report --retest 203.0.113.0/24

Review source code, locally or in CI

secskills source ./my-service
secskills source --json ./my-service > sast.json
jq '[.[] | select(.severity == "error")] | length' sast.json   # gate CI on this

source exits 0 whenever the scan ran; gate on the JSON. Needs ast-grep. Full guide

Test a build in isolation

secskills sandbox ./build-context --confirm --port 8080
secskills report --render sandbox-<tag>

No host mounts, all capabilities dropped, published to loopback only, removed afterwards. Full guide

Test an LLM app or gateway

secskills test chat.example.com --confirm --profile adversarial-readonly
secskills integrity snapshot https://gateway.example.com/v1/models --confirm
secskills integrity verify   https://gateway.example.com/v1/models --confirm

Canary reflection, system-prompt leak, response drift, and OAST-confirmed server-side fetch on OpenAI- and Ollama-style chat endpoints. Full guide

Monitor and verify fixes

secskills watch app.example.com --confirm --interval 6h

secskills attest --sign app.example.com
